# Задача 11.1 — «Три дорогі патерни — знайти й переписати»

## Метод

Три порівняння виконано через `claude -p --output-format json`, у чистих запусках без історії сесії. Токени — сума `inputTokens + outputTokens + cacheReadInputTokens + cacheCreationInputTokens` з `modelUsage` для всіх моделей. Це сума токенів API-запитів, а не унікальний розмір контексту. `total_cost_usd` — оцінка за списковими тарифами (`costBasis: list`), не рахунок Claude Pro.

## Висновок

У цих вимірах Haiku для вузької підзадачі знизив оцінку вартості на 63.4%, хоча кількість токенів трохи зросла; повне рев'ю 24 шляхів коштувало на 44 708 токенів і \$0.1971174 більше, ніж вузький огляд 8 шляхів. Найчіткіше одночасне скорочення токенів, вартості й ходів дало атомарне редагування з якісним хуком: −15 694 токени, −$0.0107232 та −3 ходи.

## Обмеження вимірювань

- Рев'ю A/B отримало однаковий перелік історично змінених шляхів, але перевіряло файли в копії проєкту, а не сам текст Git diff. Копія мала попередні видалення у `.claude/`; суворий запуск зафіксував їх окремо. Тому це вимір покриття заданого переліку, а не ізольоване порівняння якості рев'ю конкретного diff.
- Хук автоматично запускав ESLint після редагувань; окремі тести чи typecheck для цих трьох замірів не виконувалися.
- Суми токенів включають кешоване читання та створення кешу для кожного API-запиту. Вони не є дельтою довжини промпту.

## Зміни в правилах

У `CLAUDE.md` додано перевірну вимогу: рев'юер має перелічити кожен змінений шлях із Git-обсягу, включно з тестами та конфігурацією, і позначати рев'ю `INCOMPLETE`, якщо лишився неперевірений шлях. У `.claude/settings.json` задано Haiku 5.5 для субагентів.
