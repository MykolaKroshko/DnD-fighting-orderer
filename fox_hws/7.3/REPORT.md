# Задача 7.3 — «Три шари меж»

Нижче — як разом діють три частини спільного [`.claude/settings.json`](../../.claude/settings.json) і де закінчується їхній захист.

## 1. Дозволи: що Claude Code може викликати

- **`allow`** пропускає підтвердження для команд `yarn test`, `yarn typecheck`, ESLint та read-only інструментів файлового MCP-сервера. Зокрема, `yarn lint` запускає ESLint з `--fix`, тому може змінювати файли.
- **`ask`** вимагає підтвердження для Git, Node, встановлення залежностей і видалення файлів. **`deny` має перевагу**: воно блокує `git commit`, `git push`, читання `.env` і `.env.*`, вибрані shell-команди та запис через файловий MCP-сервер, навіть якщо інший шаблон просить підтвердження чи дозволяє дію.
- Ці правила вирішують, чи Claude Code може викликати інструмент. Вони не є повною ізоляцією: Bash-шаблони зіставляють текст команди, а не кожен можливий спосіб запустити ту саму програму; `Read`-заборона також не перехоплює довільний скрипт, який сам читає файл.

## 2. Змінна середовища: скільки триває команда

`BASH_DEFAULT_TIMEOUT_MS=180000` задає стандартний таймаут Bash/PowerShell-команди у 3 хвилини. Він не надає та не обмежує доступ до файлів чи мережі й не є жорсткою забороною на довше виконання: для верхньої межі існує окреме налаштування таймауту.

## 3. Sandbox: що може зробити shell-процес

- На звичайному Windows shell-команди Claude Code запускаються без sandbox. `failIfUnavailable: false` дозволяє програмі продовжити роботу без нього, тож у цьому середовищі ці filesystem- і network-обмеження не захищають shell.
- Sandbox поширюється лише на shell-команди: вбудовані файлові інструменти, MCP-сервери й hooks працюють поза ним. Для файлових інструментів тут окремо діють `Read(*.env)` і `Read(*.env.*)`, а для MCP-запису — окремі `deny`-правила.
